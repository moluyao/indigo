# 第 2 轮框架效果测试：结果（2026-11-19）

只用 Opus 5.5。A 组用青出 core v1，B 组不用框架，每组独立做 3 次（A1–A3、B1–B3）。三道新题：音乐节海报、20 秒复利科普动画、"山野咖啡"8 秒 Logo 开场。18 件作品随机编号，两位独立的 Opus 评审盲评（评审 a 站在"交给客户"的角度，评审 b 站在资深设计总监和普通观众的角度）。编号对照 `blind-key-r2.json`，评审原文 `review-r2-a.md`、`review-r2-b.md`。

## 撞车

两位评审都发现每题只有两个方向，而且**两个方向正好按组分开**：

| 题目 | B 组（无框架）撞车 | A 组（青出）撞车 |
|---|---|---|
| 海报 | 奶油纸底 + 橙红日轮 + 同一套版式，三张都写"早鸟票 ¥380"，两张都有"40+"圆章、重复的虚构乐队名 | 浅底 + 深蓝粗黑巨字 + 一个荧光色，俯视人群，空白填写栏 |
| 复利动画 | 米色讲解模板：标题 → 3 年柱状 → 30 年曲线 → 公式或要点卡；两件连数字都一样（1 万元、10%、30 年） | 黑 / 灰 / 红三色区分"本金、本金的利息、利息的利息" |
| Logo 开场 | 暗底 + 一条线升起成山 + 收进杯子 + 橙色发光圆 + 居中宽字距名字 | 满屏同心线（等高线 / 年轮）收成左侧圆标，名字在右 |

评审 b 的判断：B 组那一路是"执行最稳但被默认味封顶在 L1 的模板"；A 组那一路"从题材本身找图形想法，记忆点强，但收尾粗糙"。

## 结论

**框架有效，没有拖后腿。** 两道动态题（复利、Logo）两位评审都把 A 组排在前面；6 次"只选一件"里 5 次选了 A 组；全轮唯一的 L3 来自 A 组。框架没有限制创意，反而把作品从默认模板推向了从题材本身出发的想法。

**但框架有两个明确的问题，要修：**

1. **"不编造"规则用错了地方。** 用户没给音乐节名称、日期、阵容时，A 组选择留空白填写栏，评审把这当作未完成。正确的做法是区分两件事：关于真实世界的事实不能编；而样稿里的虚构示例内容（虚构的节名、日期、阵容）应该填上看起来真实的样例，并在过程里说明是示例。
2. **框架自己的"第二层默认"。** A 组三次之间也撞车：等高线、俯视人群加双色套印、三色分层柱。加上第 1 轮两个模型都想到"小票"，说明"避开第一层默认"之后，模型会稳定地落到同一批"聪明的第二选择"上。需要把这批第二层默认也列入禁用清单，并在发散时强制用随机发散器抽轴，而不是让模型自由挑。

**其他问题**：两组共同的硬伤是须读文字太小、停留太短、被画面裁掉，测量就能发现。原因之一是本轮所有组都不允许渲染检查，实际使用时应该允许"渲染一次、量一下、回炉一次"。

## 公平性说明

- A1 在交稿前用脚本把动画逐帧跑了一遍查报错（没有看画面），B 组没有这一步。A1 的最终名次并不靠前（两题中游、一题末位，Logo 题第一），影响有限。
- 每组每题只有 3 个样本；两位评审都是 Opus，和制作者是同一个模型，可能偏好同类作品，但评审是盲评，不知道作品出自哪一组。
