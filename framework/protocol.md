# 青出 · 执行规范（protocol）

本文件是每一步的可执行规范。每一步都必须由**独立 subagent** 执行，并严格遵守"允许读 / 禁止读"。主控（orchestrator）只负责派发、传路径、收结论，不把原料内容转述给下游。

路径记号：`<D>` 表示领域。当前约定与实际位置：

| 产物 | 约定路径 | 动效领域当前位置 |
|---|---|---|
| 原理卡 | `01-learn/<来源>.md` | 同左 |
| 骨架 | `02-forget/skeleton*.md` | `skeleton.md` + `skeleton-v2.md`（v2 覆盖的问题以 v2 为准） |
| 签名 | `02-forget/signatures.md` | 同左 |
| 禁用值 | `02-forget/avoid-list.md` | 同左 |
| 检验报告 | `02-forget/check-report-r<N>.md` | `check-report.md`（r1）、`check-report-r2.md` |
| 书 | `domains/<D>/book.md` | `03-book/动效节奏.md` |
| 标准 | `domains/<D>/standard.md` | `standards/动效.md` |
| 工具地图 | `05-tools/能力地图.md` | 同左 |

## 步骤 1：学（Learn）

- **执行者**：每个来源一个 agent，互不可见。
- **输入**：一个来源（仓库、skill、教程、案例集）的路径或链接。
- **允许读**：该来源本身。
- **禁止读**：其他来源、其他原理卡、骨架、书、签名、禁用值。
- **输出**：`01-learn/<来源>.md`，文件头写来源路径、主要读了哪些文件、领域；之后若干张原理卡。
- **要求**：
  - 问题写成**跨来源通用问题**（任何同领域来源都可能回答的问题），不要写成"该来源某功能怎么用"。
  - 每张卡必须有证据（文件:行号或链接锚点）。
  - "签名特征"一栏必须尽量写全：具体数值、曲线、命名、口号、工具命令、独特结构。这一栏是之后"忘"与"检验"的依据。
- **通过条件**：每卡七栏齐全；每卡至少一条证据；问题不含来源名。

### 模板：原理卡

```markdown
## 卡N：<跨来源通用问题，问句>
- 这家怎么解：<具体做法，可含数值与流程>
- 为什么有效：<机制层面的解释：感知、认知、物理、工程>
- 代价与边界：<何时失效、需要什么前提、副作用>
- 反例：<原文案例或可推出的失败形态；若有"故意违反"也写这里>
- 签名特征：<可辨识这家的值/结构/术语/命令>
- 证据：<路径:行号；路径:行号>
```

## 步骤 2：忘 / 剥离（Forget）

- **执行者**：一个剥离 agent（不同于学与重写的 agent）。
- **输入**：全部原理卡。
- **允许读**：`01-learn/*`、已有 `02-forget/*`（增量时）。
- **禁止读**：书（避免以书反推骨架）。
- **输出三份**：
  1. `skeleton.md`：按问题合并卡片，每个问题一个条目，编号 Q1、Q2……（增量时新问题用新编号，旧编号永不重排）。
     - **只允许**：问题、原理、需权衡变量、边界与反例方向、共识强度、知识缺口。
     - **禁止**：来源名、任何数值/区间/比例、曲线名、具体解法、清单式规则、口号原句。
     - 若第一版骨架仍含过多"答案"，出第二层抽象（`skeleton-v2.md`），只写"要回答的问题 + 变量 + 原理"，把"怎么做"全部留给重写者推导。
  2. `signatures.md`：被剥离下来的签名，格式"来源 → Q 编号 → 具体做法/参数"。**仅检验者可读**。另设"工具 / 行业默认值"一节。
  3. `avoid-list.md`：禁用值，只列值或结构，不写来源与用途。**必须包含行业默认值与工具出厂值**（见下方"关键发现"）。
- **通过条件**：在骨架中检索任何来源名、数字（编号除外）、签名中的术语，命中数为 0。

### 模板：骨架条目

```markdown
## Q<编号>：<短标题>

**问题**：<要回答的问题；可拆为两三个子问>

**需要权衡的变量**
- <变量 1：它由什么决定、在什么范围内变化（不写数值）>
- <变量 2>

**原理**
- <一句机制陈述：为什么这个变量会影响结果>
- <冲突时的取舍原则>

**边界与反例**（保留方向）：<失败形态的方向描述，不带数值与来源>

**共识强度**：<强：多来源一致 / 中：多数一致有分歧 / 弱：单一来源或互相矛盾>

**知识缺口**：<来源都没回答、或回答互相矛盾的子问题>
```

### 模板：禁用值条目与规则头

```markdown
## 规则
1. 本清单只列"值/结构"，不说明来源和用途。
2. 重写者若使用任何一项，必须写出"非它不可"的第一性原理推导；写不出就必须偏离。
3. "使用"的判定：
   - 曲线：控制点各自相差 ≤ 0.05 视为同一条。
   - 单个数值：相差 ≤ ±10% 视为同一个。
   - 区间：取值落入清单区间，或区间重叠超过一半。
   - 序列/切分：结构同构（同样的长度比、加倍/减半模式、切分比例）即视为使用。
   - 多参数组：多数参数命中即视为使用。
4. 标"行业默认"的条目不是"错"，但用它等于没做选择，同样适用第 2 条。
5. 偏离不等于随手改一个数：偏离后的值同样要有推导。

## <分类，如：曲线 / 时长 / 比例 / 序列 / 结构>
N. <值或结构>（行业默认）   ← 仅默认值加此标记
```

### 关键发现：默认值也要禁

第 1 轮检验发现，即使重写者从未见过原料，它仍会因模型自身的"默认习惯"写出与原料一致的值（常见缓动、常见时长、常见切分）。这类复现与抄袭在结果上无法区分。所以 avoid-list 必须收录：公开库默认值、平台规范默认值、工具出厂参数，以及检验中发现的"模型惯用值"。

## 步骤 3：重写（Rewrite）

- **执行者**：一个重写 agent，与前两步的 agent 完全隔离。
- **允许读**：`skeleton*.md`、`avoid-list.md`、（可选）领域通用的物理/感知常识；退回重写时可读本章的检验意见**结论部分**（只含判定与需偏离的维度，不含签名原文）。
- **禁止读**：`01-learn/*`、`signatures.md`、任何原始来源、旧版书中被判复现的段落原文。
- **输出**：书 `book.md`。
- **体例**（参照 `03-book/动效节奏.md`）：
  1. 开篇：本领域的若干条第一性原理。
  2. 每章对应一个或多个 Q 编号，结构为：**推导**（从变量与原理推出本章的决策方式）→ **至少三种取向**（例如克制型 / 冲击型 / 物理驱动型；取向之间应在机制上不同，而不是同一做法的强弱档）→ **故意违反**（什么时候该反着做，代价是什么）→ **自检问题**。
  3. 书末：**速查表**（问题 → 各取向的决策要点）与 **禁用值自查附录**（"命中且保留"表：命中了哪一项、正文推导在哪里；以及"已偏离"列表）。
- **规则**：
  - 命中禁用值时，正文必须写出"非它不可"的推导；否则偏离，偏离值也要推导。
  - 骨架的知识缺口要正面回应（给出推导出的方案，或明确标为开放问题）。
  - 不得出现任何来源名。

---

## 步骤 4：检验（Check）

- **执行者**：独立检验 agent（不参与重写）。
- **允许读**：书、`signatures.md`、`avoid-list.md`、骨架（用于判"骨架泄漏"）、上一轮检验报告与上一版书（用于对比）。
- **输出**：`check-report-r<N>.md`，含判定口径、总数表（按来源与按严重度）、逐条判定、按章汇总、退回清单。

### 判定口径

| 判定 | 含义 |
|---|---|
| 复现 | 骨架里没有、且有辨识度的参数或手法与签名几乎一致（数值 ±10%、落入对方区间、结构同构、公式相同）。分 **重**（多参数/成套结构一致，或核心公式一致）、**中**（单个关键值一致）、**轻**（常见值，巧合可能大） |
| 趋同 | 方向一致但参数或表达不同；或一致之处已写在骨架里（骨架泄漏，记入骨架问题） |
| 分化 | 做法与该来源明显不同或相反 |
| 新增 | 书中有、所有来源与工具卡都没有的解法（单独计数） |

- 一条签名有多个子项时，任一子项复现即整条判复现，按最重子项定级。
- **申报**：复现项若已列在附录"命中且保留"表、且正文推导确实成立，标"已申报"，仍计入复现数，但不单独触发退回；未申报的照常触发。

### 通过阈值

- **任一章节：重 ≥ 1，或 中 ≥ 2（均指未申报或推导不成立者）→ 该章退回重写。**
- 全书无退回章节即通过。轻度复现只记录，不退回。
- 循环：退回 → 重写（仅退回章节）→ 检验 → ……直到通过。每轮编号递增，旧版书移入 `archive/`。

### 模板：检验条目

```markdown
| 签名 | 来源代号 | Q | 书中位置 | 判定 | 级别 | 已申报 | 说明 |
|---|---|---|---|---|---|---|---|
| <签名摘要> | A | Q2 | 第2章·冲击型 | 复现 | 中 | 否 | <哪一项值/结构一致、差距多少> |
```

报告中来源用代号（A、B、C…），便于报告本身流转时不泄露来源细节。

## 步骤 5：增量吸收（新来源）

1. 学：只为新来源开 agent，产出新原理卡。
2. 并入骨架：剥离 agent 读新卡与现有骨架，归入已有 Q 或追加新 Q（新编号），更新共识强度与缺口；记录"受影响 Q 列表"。
3. 补签名与禁用值：signatures 追加新来源一节；avoid-list 追加新值。
4. 只重写受影响章节：重写 agent 收到"受影响 Q 列表"，只改对应章节与附录。
5. 检验：受影响章节对全部签名比对；其余章节只对新来源签名比对。按同一阈值退回。
6. 防偏移检查：独立 agent 按 `charter.md` 第六节逐项检查；任一项不过，本次吸收退回，不并入。通过后写入 `CHANGELOG.md`。

进入第 1 步之前，先按 `charter.md` 第五节给来源分类：不是 skill/方法论的东西（提示词、作品、工具、数据、用户判断）走各自的入口，不硬套这五步。

## 步骤 6：质量标准（Standard）

标准与书分开写、分开改：书讲"怎么想"，标准讲"怎样算好"。每个领域一份 `standard.md`（动效当前为 `standards/动效.md`）。

### 通用结构

1. **底线（Floor）**：可量化、脚本可检的硬指标，过不了直接 L0/L1，不进评审。每条写明：指标、阈值、测量方法（脚本或命令）、对应书中章节。
2. **上限（Ceiling）**：用标杆参照做**两两比较**（本作 vs 标杆，逐维度判"更好/相当/更差"），而不是绝对打分。每个维度写明：维度、标杆样本、比较问题、对应书中章节。
3. **分级**：
   - L0 坏：底线不过，有明显缺陷。
   - L1 能用：底线通过，但平淡或有可感知瑕疵。
   - L2 商业合格：底线全过，上限各维度不劣于"合格标杆"。
   - L3 精品：多数维度优于合格标杆，与"精品标杆"相当。
   - L4 惊艳：至少一个维度超过精品标杆，且其余不劣。
4. **爆款轴**：播放、完播、互动等数据是**独立轴**，不混入 L0–L4，不作为质量判定依据，只用于复盘。
5. **角色分离**：做作品者不得评审自己的作品；评审 agent 只读作品、标准与标杆，不读制作过程的自我说明。
6. **回炉路径**：不达标 → 定位失分维度 → 查维度对应的书中章节 → 按该章回炉 → 重新底线 + 评审。
7. **回流**：评审结论与上线数据定期汇总；反复失分的维度→修订书中对应章节（走重写 + 检验）；标杆过时或阈值不合理→修订标准。

### 模板：标准条目

```markdown
### 底线 F<编号>：<指标名>
- 阈值：<可量化条件>
- 测量：<脚本/命令/方法>
- 不过时：<判 L0 或 L1>
- 对应章节：<书中第 N 章>

### 上限 C<编号>：<维度名>
- 标杆：<合格标杆 / 精品标杆，各给样本>
- 比较问题：<两两比较时要回答的具体问题>
- 判定：更好 / 相当 / 更差（附一句理由）
- 对应章节：<书中第 N 章>
```

## 步骤 7：创作（Make）

1. 定目标级别（L2/L3/L4），写入作品目录 `04-create/<作品>/brief.md`。
2. 创作 agent 读书 + 工具地图（`05-tools/能力地图.md`），每章选取向并记录理由。
3. 底线脚本检查：不过则先修，不进评审。
4. 上限评审：独立评审 agent 按标准两两比较，给出级别与失分维度。
5. 未达目标级别 → 按"回炉路径"定位章节，回到第 2 步；达到 → 通过。
6. 复盘：发布后记录数据轴，与评审结论一起写入 `04-create/<作品>/review.md`，定期回流修订书与标准。

| 忘 | 否 | 是 | 是（写） | 是（写） | 是（写） | 否 | 否 |
| 重写 | 否 | 否 | 是 | **否** | 是 | 是（写） | 否 |
| 检验 | 否 | 可选（核证据） | 是 | 是 | 是 | 是 | 否 |
| 创作 | 否 | 否 | 否 | 否 | 可选 | 是 | 是 |
| 评审 | 否 | 否 | 否 | 否 | 否 | 可选（定位章节） | 是 |
