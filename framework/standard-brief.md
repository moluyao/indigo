# 「写标准」指令（给每个写标准的 subagent）

你在为青出框架的一个领域写**质量标准**：回答"这个领域的作品，什么叫好、什么叫不好、怎么判"。根目录 ``。

## 先读
- `framework/charter.md`：公理 2「标准固定，风格开放」——标准评的是**观众一侧看到的效果**，不规定手法；不得把书里任何一种取向写成要求，也不得给某种取向扣分。
- 结构范本：`standards/动效.md`（只学结构：底线分「交付技术层 T」和「观众可感层 B」、维度 D 的 L1–L4 可观察特征、AI 低级感清单、回炉指向书的章节、评审卡、判级规则、标杆库规范、自动检查清单）。**不要照搬它的内容**；它有三处已知问题不要学：B-12「主焦点唯一」排除了多焦点做法；把「整屏完全静止」列为预警；L3 要求「全片一致的物理人格」——这些都是在替某种取向判分。
- 本领域的书（r5）：每章的「失败点预判」「自检问题」，尤其标了可测量的条目，是标准条目的主要来源。
- 外部规范：`reference/WCAG-2.3.1-闪烁阈值.md`（闪烁一律以此为准）。对比度用 WCAG 相对亮度公式（正文 ≥ 4.5:1、大号字 ≥ 3:1，大号字的条件要写清）。声画同步引用 ITU-R BT.1359。平台响度不写具体数，写"以平台实测为准"的求法。
- 真实失误数据：`eval/analysis-r1r2.md`、`eval/review-opus.md`、`eval/review-fable.md`、`eval/review-r2-a.md`、`eval/review-r2-b.md`、`eval/rubric-v1.md`。两轮盲测里评审实际抓到的问题（字太小、被裁、遮挡、空白占位、停留太短、全程匀速、默认模板味），是底线该先管什么的依据。

**不读**：`01-learn\`、任何 `signatures.md`、`00-sources\`、各领域 `check-report*.md`。

## 写什么（`standards/<领域>.md`）
1. **总则**：评什么、不评什么；做片者交付时附的「评审卡」（目标级别、目标时长或画幅、平台、核心信息一句话、须读文字范围、样稿示例内容清单）；评审者只看成品和评审卡，不看制作过程。
2. **底线**：
   - 交付技术层 T：可在导出时机械修复的（编码、色彩元数据、尺寸、帧率等）。不达标记为"交付未过"，附自动修复方法，不把作品判为 L0。
   - 观众可感层 B：观众看得见、听得见的错误（读不完、看不见、被裁、遮挡、空白占位、穿帮、闪烁超限……）。不达标才判 L0。
   - 每条写：指标、阈值、测量方法（脚本或人工步骤）、阈值的依据（规范原文 / 书的哪一章推导 / 待实验）、不达标时回炉看书的哪一章哪一节。
3. **上限维度**：每个维度写判断问题、L1→L4 各级「看到什么」（写现象，不写手法和参数）、典型 AI 低级感、回炉指向。必须包含「创意与新鲜度」和「执行与完成度」两个可以单独打分的维度（两轮盲测证明这两项要分开看），以及「第二层默认」识别（命中只扣新鲜度，不判错）。
4. **判级规则**：底线、维度、短板如何合成综合级别；某维度无法评（例如评审听不了声音）时如何写；版本对比用维度差分表，允许"持平"。
5. **样稿内容口径**：明显是示例的虚构名称、日期、价格不算编造；留空白填写栏或占位线算未完成；"决定类"内容（价格、时间、地点）要标"发布前须用户确认"。
6. **标杆库规范**：每级放什么样的锚点作品、每件怎么标注（为什么是这个级别、哪个维度）、正例与反例；标杆只给评审看，不给做作品的人看；第一批锚点用两轮盲测里两位评审意见一致的作品（两位都给 L3 的作正例，两位都判"默认模板"的作反例），只写作品编号和理由，不写画面内容描述以外的东西。
7. **自动检查清单**：能用脚本测的条目单列，写清测量方法，编号要能和底线对上。
8. **文件头**：写明依据的书版本（例如"依据：视觉设计 book r5，2026-11-19"）——流程纪律第 8 条。

## 规则
- 每个阈值都要有依据：规范原文、书的推导，或者标「待实验」。不写没有来源的数。
- 不得出现两轮盲测和第 3 轮可能用到的具体题目示例。
- 分段写：先 Write 开头和总则并保存，之后每次用 Edit 追加一节，每段不超过约 3000 字。UTF-8，禁止 PowerShell Get-Content/Set-Content。

回复：维度数、底线条数（T / B）、自动检查条数、待实验的阈值有几个。
