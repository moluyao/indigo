# 公开发布注意事项

## 建议公开

- `framework/`（README、protocol、本文件）与 `SKILL.md`：框架本身是我们的方法。
- 我们自己的**书**（如 `03-book/动效节奏.md`）：经过检验、复现已降到阈值以下，属于重写产物。发布前再确认附录"命中且保留"表中只有行业通用值、且每项都有推导。
- 我们自己的**标准**（如 `standards/动效.md`）：注意其中"标杆样本"若引用他人作品，只给链接，不嵌入截图或片段。
- `02-forget/skeleton*.md`：只含问题、原理、变量，可公开；发布前再检索一遍来源名与数值。
- `05-tools/能力地图.md`：引用的是公开开源库，可公开，保留各库链接。

## 建议不公开（或只公开来源链接清单）

- `01-learn/`：原理卡里有他人作品的具体做法、参数、案例与文件行号，属于对他人作品的详细摘录。
- `02-forget/signatures.md`：同上，是按来源整理的具体解法与参数。
- `02-forget/avoid-list.md`：虽不写来源，但值本身就是他人的具体参数集合，逆向可还原。
- `02-forget/check-report*.md`：含签名摘要与逐条比对，同样不公开；可只公开总数表。
- `04-create/` 中的私有素材、账号数据。

替代做法：公开一份**来源清单**（来源名 + 仓库/页面链接 + 许可证），说明"本书由这些来源经青出流程重写，原理卡与签名不公开"。

## 致谢与许可证

- 每个来源在来源清单中保留**致谢与原始链接**，并注明其许可证（MIT / Apache-2.0 / CC 系列 / 未声明等）。
- 来源未声明许可证的，默认视为保留所有权利：不公开任何摘录，只给链接。
- 带 CC-BY-SA、GPL 等相互性条款的来源：若书中有可识别的派生内容，需评估是否触发相同许可要求；以检验报告中"复现"为空作为降低风险的依据，但不等于法律意见。
- 工具地图中引用的开源库按其各自许可证标注。
- 我们自己的框架、书与标准，请在仓库根目录写明自身许可证。

## 发布前检查

1. 在待发布文件中检索所有来源名、来源独有术语与命令名，命中为 0。
2. 在书中检索 avoid-list 中的值，命中项都在附录有推导。
3. 不出现个人账号、素材署名或站外引流信息。
