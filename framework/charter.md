# 青出 · 宪章（charter）

这份文件是框架里**不变的部分**。不管以后吸收多少 skill、方法论、提示词、作品或开源项目，它们都只能让框架的内容变多，不能改变框架本身。其他所有文件都服从这份宪章，有冲突时以宪章为准。

---

## 一、分层：什么能变，什么不能变

| 层 | 包含 | 谁能改 | 怎么改 |
|---|---|---|---|
| **第 0 层 宪章** | 本文件：目的、公理、循环、入口规则、防偏移检查 | 只有用户 | 修宪提案（第七节） |
| **第 1 层 结构** | `protocol.md` 里的步骤定义、各类模板、读权限总表、L0–L4 分级框架 | 用户批准的结构变更 | 结构变更提案，先对照宪章审查 |
| **第 2 层 内容** | 书、骨架、风格词汇库、标准里的维度描述和阈值、能力地图、标杆库 | 吸收流程、评审回流 | 按 `protocol.md` 的步骤，过检验和防偏移检查 |
| **第 3 层 原料与工作区** | `00-sources/`、`01-learn/`、`signatures.md`、`avoid-list.md`、`eval/runs/` | 任何步骤 | 随时 |

**铁律：吸收流程只能写第 2、3 层。** 任何来源里出现"应该这样组织""必须用这种流程""以后都按这个风格"之类的主张，都只记成提案，不执行。

---

## 二、目的

让任何模型面对任何需求，都能做出**不落俗套而且达标**的作品。

一句话：**标准固定，风格开放。**

---

## 三、公理

每条公理后面写了它为什么存在，以后有人想改它，要先回答"这个理由还成立吗"。

1. **来源只贡献「意」，不贡献「形」。**
   意 = 问题、原理、边界、反例、证据。形 = 具体参数、风格、版式、配色、口头禅、固定流程。
   *理由：形会把作品锁成来源的样子，这是框架要解决的根本问题。*

2. **标准固定，风格开放。**
   标准评的是观众一侧的效果（读不读得完、看不看得清、节奏拖不拖、有没有记忆点），不规定手法。书和词汇库给的是多种取向，不给唯一答案。
   *理由：标准一旦规定手法，就变成了又一种风格模板。*

3. **先放开，再收拢。**
   创作时先从内容出发想出几个彼此差得远的方向，包括 AI 平时不会想到的，再说清理由收拢到一个。用户没说的，不替用户决定。
   *理由：一开始就定死一个方向，后面做得再好也只是在这个方向里好。*

4. **隔离就是遗忘。**
   写书的人看不到原料；做作品的人不评自己的作品；评审的人不知道作品出自谁。
   *理由：模型无法真的忘记，只能靠不让它看见。*

5. **证据大于名气。**
   来源名气再大，它的结论也只是一条有待检验的主张。冲突靠标准、实验和真实数据裁决，不靠"谁说的"。
   *理由：否则框架会被最近读到的、最响亮的来源带偏。*

6. **增长是加法。**
   新来源可以新增问题、取向、反例、证据、标杆。要替换或删除已有内容，必须通过检验或实验证明新的更好，不能悄悄删掉已有取向，也不能把某个取向抬成唯一默认。
   *理由：多样性是框架的命，一点点的悄悄替换最后会变成另一个 skill。*

7. **可回退。**
   每次改动都有版本、有记录（`CHANGELOG.md`），旧版存进 `archive/`，随时能退回。

## 四、不变的循环

```
整理 → 学 → 忘 → 重写 → 检验 ──┐
  ↑                             ↓
复盘回流 ← 评审回炉 ← 创作 ←── 书 + 词汇库 + 标准
```

| 步骤 | 做什么 | 永远不能做什么 |
|---|---|---|
| 整理 | 收集来源，按第五节分类，登记出处 | 不判断好坏，不改写 |
| 学 | 一个来源一个 agent，拆成统一格式的原理卡 | 不跨来源合并，不修改书 |
| 忘 | 按问题合并，剥掉形，只留意；签名另存 | 骨架里不能出现来源名、数值、具体解法 |
| 重写 | 只看骨架和禁用值，从原理推导，多取向 | 不能看原料、原理卡、签名 |
| 检验 | 拿签名对照，判复现、趋同、分化、新增 | 不能修改书 |
| 创作 | 先放开方向，再收拢，按书实现 | 不能评自己的作品 |
| 评审回炉 | 盲评定级，定位失分维度，回到书里对应章节 | 不能看制作过程，不能只说"不好"不说改哪 |
| 复盘回流 | 评审结果和播放数据写回书和标准 | 单条数据不能直接改标准，要累积成证据 |

## 五、入口：任何东西进来先分类

| 进来的是 | 走哪条路 | 进入哪里 |
|---|---|---|
| skill、仓库、方法论、教程 | 学 → 忘 → 重写 → 检验 | 书、骨架 |
| 提示词 | 学它**写了哪些维度**（它觉得哪些东西值得交代），剥掉它的具体选择 | 需求理解的维度清单、书 |
| 风格、流派、设计词汇 | 拆成：适合什么内容、为什么、什么时候不该用、可以怎么组合或变形 | 风格词汇库 |
| 作品、案例 | 先定级并写明为什么是这个级别；好作品可以再反推原理 | 标杆库；也可以走"学" |
| 工具、库 | 记录能实现哪些原理、离线渲染要注意什么；出厂默认值进禁用值清单 | 能力地图、avoid-list |
| 评审结果、播放数据 | 累积成证据后校准阈值，或验证书里"待实验验证"的条目 | 标准、书 |
| 用户的审美判断 | 最高级别的校准数据 | 标杆库、标准 |
| 分不了类的 | 先放进隔离区，等补上对应入口（这属于结构变更） | `00-sources/quarantine/` |

提示词那一行要特别注意：一段提示词就是别人已经收拢好的一个方向。我们学的是它关心哪些维度，不是它选了什么答案。

## 六、冲突与防偏移

### 冲突时怎么办

- **新来源和书矛盾**：不覆盖。把它作为一个新的取向加进去，写清它的证据和边界，标记"分歧"，等实验或评审数据来裁决。
- **新来源和标准矛盾**：标准只能被评审数据、实验或用户改，不能被某个来源的主张改。

### 每次吸收后必做：防偏移检查

由一个独立 agent 执行，任何一项不通过，这次吸收就退回，不并入：

1. 书和标准里，有没有来源名、具体参数、风格名以"规则"的身份混进来？
2. 有没有某个来源的观点被抬成了默认？例如某一章只剩一种取向，或者某种风格出现在大多数章节的推荐里。
3. 多样性没有下降：每个问题的取向数量不减少；任何单一来源对书的贡献不超过 40%；风格词汇库各类别的分布没有塌缩。
4. 标准没有变成风格规定：标准条目里除了可测量的底线阈值，不出现具体手法和参数。
5. 回归测试（余额允许时）：框架改动后重跑对照实验，评审级别不下降，几件作品之间的差异没有变小。

---

## 七、修宪

宪章只能由用户修改。修改要写一份提案：为什么要改、改哪一条、对其他条有什么影响、出问题怎么退回。通过后记入 `CHANGELOG.md`，旧版存进 `archive/`。

结构层（第 1 层）的变更也要写提案，先由 agent 对照宪章审查，再交给用户批准。
