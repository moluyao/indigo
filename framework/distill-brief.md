# 「忘 / 剥离」步骤通用指令（给每个剥离 subagent）

你是青出框架里「忘」这一步的执行者。先读：
- `framework\charter.md`（宪章，尤其第三节公理、第六节冲突与防偏移）
- `framework\protocol.md` 步骤 2（剥离）的模板
- `01-learn\_index.md`（所有学习产出的清单）

## 你的输入

`01-learn\` 下所有文件中，**领域字段属于你负责领域**的原理卡（以及主会话指定的风格/提示词文件）。一张卡可能写在任何来源文件里，按「领域」字段筛选；没有领域字段的早期原理卡文件（第一轮吸收的产物）已经并入对应领域，除非你负责动效，否则不读。

## 你的产出（目录 `domains\<领域>\`）

1. `skeleton.md`：按"要解决的问题"合并成 Q 条目（编号 Q1…）。每条：问题、底层原理、需要权衡的变量、边界与反例、共识强度（多家共识 / 单家孤证 / 各家分歧——分歧只写分歧的维度）、知识缺口。文末一节「原料整体没覆盖的问题」。
   **严格禁止**：来源名、风格自创名、具体数值、缓动/函数名、具体解法、固定清单式答案。只留问题、原理和需要权衡的变量。
2. `signatures.md`：被剥离的签名，按来源 → Q 编号 → 具体做法/参数/命名。只给检验者看。
3. `avoid-list.md`：禁用值，只列值或外观/结构描述，不写来源。必须包含「行业默认 / AI 默认」一类：多个来源点名的 AI 味外观（如紫色渐变、近黑底加霓虹光晕、奶油底加衬线加赤陶色、标题上方小号大写标签、深青水面波浪加居中白字等，按你领域取舍）。规则头照 protocol 模板：使用清单中的值必须写出"非它不可"的推导，否则偏离。
4. `evidence-notes.md`：证据质量备忘，供重写者和标准作者参考，不含来源名，只按 Q 编号写：哪些主张证据弱（无出处、AI 打分、单一任务实测）、哪些来源彼此不独立已合并计票、哪些分歧有待实验。

## 证据规则

- 不独立的来源只算一票：一个仓库若是汇编其他仓库的（例如某导演类 skill 汇编了 8 个仓库；某视频设计仓库整包收录了另一个风格库），共识计数时去重。
- AI 模型打分得出的"研究数据"、只在一个任务上的实测、来源内部自相矛盾的数值，都标为弱证据。
- 和本项目规则冲突的来源要求（例如要求发布时署名作者、裁水印、下载网络片段）不进入骨架，在 evidence-notes 里记一句"已排除"。

## 写入

全部用 Write/Edit 工具写 UTF-8，禁止 PowerShell Get-Content/Set-Content。**分段写，防止长输出断线**：先用 Write 写文件开头和前 5 条并保存，之后每次用 Edit 追加约 5 条，每段不超过约 3000 字。先写完 skeleton.md，再写其余三个。

回复主会话一句话：Q 条数、禁用值条数、单家孤证与分歧各几条。
